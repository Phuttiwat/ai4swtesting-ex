You didn't include your team's test idea format, and the course material doesn't define one. I used a plain "Verify that … when …" one-liner instead. If you paste an example of your format, I'll rewrite the ideas to match.

| # | Test idea | Technique |
|---|---|---|
| 1 | Verify that a password of exactly 8 characters with one digit and one uppercase letter (e.g. `Abcdefg1`) is accepted. | Lower boundary |
| 2 | Verify that a password of exactly 20 characters with one digit and one uppercase letter is accepted. | Upper boundary |
| 3 | Verify that a 7-character password with a digit and an uppercase letter (e.g. `Abcdef1`) is rejected as too short. | Just below the lower boundary |
| 4 | Verify that a 21-character password with a digit and an uppercase letter is rejected as too long. | Just above the upper boundary |
| 5 | Verify that a valid-length password with an uppercase letter but no digit (e.g. `Abcdefgh`) is rejected. | Missing a required character class |
| 6 | Verify that a valid-length password with a digit but no uppercase letter (e.g. `abcdefg1`) is rejected. | Missing a required character class |

Ideas 1–4 are boundary value tests on the length rule. Ideas 5–6 cover each character requirement being missing on its own, with the length held valid, so a failure points to one rule.

Other ideas I left out to keep to six:
- An empty password.
- A password with neither a digit nor an uppercase letter.
- Non-ASCII uppercase letters.
- A password made only of digits and uppercase letters.

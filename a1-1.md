# Test Plan: File Upload Feature

## 1. Assumptions (edit to match the real system)

| Parameter | Assumed value |
|---|---|
| Allowed types | JPG, PNG, PDF |
| Max file size | 5 MB (5,242,880 bytes) |
| Min file size | > 0 bytes |
| Files per request | 1 to 5 |
| Auth | Logged-in users only |
| Storage | Server-side, original name sanitized, unique stored name |

## 2. Scope and techniques

- **Black-box:** Equivalence Class Testing (ECT), Boundary Value Analysis (BVA), Decision Table.
- **Levels:** Functional/system, security, performance, usability.
- **Out of scope:** virus-scanner internals, CDN behavior.

## 3. Equivalence classes

| Input | Valid classes | Invalid classes |
|---|---|---|
| Type | V1: jpg, V2: png, V3: pdf | I1: exe, I2: txt, I3: no extension, I4: double extension (`a.pdf.exe`), I5: extension/content mismatch |
| Size | V4: 1 B – 5 MB | I6: 0 B, I7: > 5 MB |
| Count | V5: 1–5 files | I8: 0 files, I9: > 5 files |
| Name | V6: normal ASCII/Thai/Unicode | I10: path traversal, I11: very long (> 255), I12: special chars / null byte |
| Session | V7: authenticated | I13: unauthenticated, I14: expired token |

## 4. Boundary values (size, max = 5,242,880 B)

| Case | Size | Expected |
|---|---|---|
| Below min | 0 B | Rejected: empty file |
| Min | 1 B | Accepted |
| Min+1 | 2 B | Accepted |
| Nominal | 2 MB | Accepted |
| Max−1 | 5,242,879 B | Accepted |
| Max | 5,242,880 B | Accepted |
| Max+1 | 5,242,881 B | Rejected: too large |

File count boundaries: 0 (reject), 1, 2, 4, 5 (accept), 6 (reject).
